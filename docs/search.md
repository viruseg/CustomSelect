# Поиск

## Включение

Поле поиска показывается при `searchable: true` (по умолчанию включено) и получает фокус при открытии списка кликом.

```js
new CustomSelect('#host', {
    searchable: true,
    searchMode: 'contains',
    searchCaseSensitive: false,
    highlightSearchMatches: false,
});
```

При закрытии списка запрос очищается; при повторном открытии поле пустое.

## Режимы (`searchMode`)

| Режим | Правило | Пример: запрос `car` найдёт |
|---|---|---|
| `contains` (дефолт) | Подстрока в любом месте | «my **car**», «**car**go» |
| `startsWith` | Совпадение с начала строки | «**car**go»; «my car» — нет |
| `exact` | Полное совпадение всей строки запроса с полем | «car» найдёт только элемент с content ровно «car» |
| `fuzzy` | Подпоследовательность: символы запроса идут в том же порядке, но не обязательно подряд | «c**a**r» → «c**a**r», а «ap» → «**a**pple» |

Нечёткий поиск сознательно реализован как subsequence matching без Levenshtein-скоринга — этого достаточно для списков порядка сотен элементов и работает мгновенно.

## Нормализация

- Query обрезается по краям и разбивается по пробелам на токены.
- Unicode-нормализация **NFKC применяется всегда** (полноширинное `Ａｐｐｌｅ` совпадает с `apple`).
- Приведение к нижнему регистру — если `searchCaseSensitive: false` (по умолчанию).

## Семантика: OR по полям × AND по токенам

Многословный запрос «red car» означает: найти элементы, где **каждый токен** найден хотя бы **в одном из полей**.

Пример:

```js
items: [
    { id: 1, type: 'text', content: 'Red Car', searchKeywords: ['vehicle'] },
]
```

Запрос `"red vehicle"` → **совпадение**: токен `red` нашёлся в content, токен `vehicle` — в keywords.

Запрос `"blue vehicle"` → нет (токена `blue` нет ни в одном поле).

## Поля поиска

- Для `type: 'text'`: `content` + все `searchKeywords`.
- Для `type: 'image'`: только `searchKeywords` — URL картинки никогда не участвует в поиске.

Поэтому для image-элементов ключевые слова фактически обязательны, чтобы их можно было найти:

```js
{
    id: 7,
    type: 'image',
    content: '/img/red.png',
    searchKeywords: ['красный', 'red'],
}
```

## Порядок результатов

Поиск **фильтрует**, но не сортирует: порядок совпадений всегда соответствует исходному порядку `items`. Никакого score-ranking.

## Выбранные элементы в результатах

По умолчанию выбранные элементы остаются видны в отфильтрованном списке — чтобы можно было снять выбор прямо из него. Скройте их опцией:

```js
showSelectedItems: false,
```

## Подсветка совпадений

```js
highlightSearchMatches: true,
```

Совпадающие части текста оборачиваются в `<mark class="csel-hl">`. Реализация полностью безопасна: пользовательский контент разбивается на текстовые узлы и `mark`-элементы, HTML из данных не интерпретируется никогда.

Подсветка размечает позиции каждого токена; в режиме `exact` подсвечивается полное совпадение строки запроса; в fuzzy — жадные позиции символов подпоследовательности.

## Пустые состояния — три разных

| Состояние | Когда | Что показывается |
|---|---|---|
| Loading | `loading: true` | Спиннер |
| Empty list | `items` пуст или все disabled | `emptyListText` |
| Empty search | элементы есть, но запрос ничего не нашёл | `emptySearchText` |

## Клавиатура в поиске

- Фокус при открытии через клик попадает в поле поиска — печатать можно сразу.
- `ArrowDown` уводит активность на первую опцию списка (фокус остаётся в поле, ввод не прерывается).
- `Escape` закрывает popover целиком (запрос очищается).
